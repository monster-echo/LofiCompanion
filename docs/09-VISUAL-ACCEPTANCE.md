# 视觉验收与截图回归

版本：0.1  
目标：保证 React Native 实现与已批准原型在构图、层级、色彩和交互状态上可证明地一致。

## 1. 设计真源优先级

发生冲突时按以下顺序处理：

1. `08-SCREEN-SPECIFICATIONS.md`：文字、行为、页面结构和状态。
2. `07-VISUAL-DESIGN-SYSTEM.md`：令牌、尺寸、字体、动效和媒体安全区。
3. `assets/prototypes/*.png`：整体构图、氛围、信息层级和视觉重心。
4. 平台规范：安全区、商店购买、系统权限和无障碍要求。

原型图由图像模型生成，可能含微小文字或图标误差，不能从栅格图抄写假文本。实现必须保持
原型的视觉意图，同时使用文档中的真实组件和文案。

任何偏离批准设计的修改必须在 PR 中写明原因、前后截图和批准记录；“技术上更方便”不是
有效偏离理由。

## 2. 必须建立的设计基线

React Native 开发开始前创建：

```text
.interface-design/system.md
src/theme/primitives.ts
src/theme/semanticTokens.ts
src/design-system/*
e2e/fixtures/design-state.json
e2e/visual-baselines/390x844/*
e2e/visual-baselines/360x800/*
e2e/visual-baselines/430x932/*
```

本目录已有 `.interface-design/system.md` 作为实现约束摘要。代码令牌必须从文档转写，
不能在页面中散落同义常量。

## 3. 固定截图数据

视觉测试必须使用固定时区 `Asia/Shanghai`、固定日期、固定本地化 `zh-CN`、固定用户和
固定 poster，不播放随机视频帧。

建议 fixture：

```json
{
  "now": "2026-08-29T20:18:00+08:00",
  "user": { "displayName": "我" },
  "skin": "rainy-study-room-v1",
  "todayMinutes": 50,
  "todaySessions": 2,
  "weekMinutes": 180,
  "weekTargetMinutes": 300,
  "activeRemainingSeconds": 1458,
  "leaderboardRank": 12
}
```

媒体 fixture 必须有 ready、focusing、drinking、completed 四张固定 poster，并使用与生产
视频相同的裁切焦点。真实视频只进入播放器集成测试，不进入像素基线。

## 5. 截图设备矩阵

| 设备档 | 画布 | 字体缩放 | 用途 |
|---|---:|---:|---|
| 小屏 | 360×800 | 1.0 | 检查 CTA 和媒体裁切 |
| 标准 | 390×844 | 1.0 | 主批准基线 |
| 大屏 | 430×932 | 1.0 | 检查留白和比例 |
| 标准无障碍 | 390×844 | 1.3 | 文本换行和卡片增高 |
| 标准减少动态 | 390×844 | 1.0 | poster 降级和无位移动效 |

iOS 与 Android 都要有标准设备截图。平台字体渲染允许建立独立基线，不能用一个平台截图
替另一个平台通过。

## 6. 几何验收公差

标准画布下：

- 页面横向边距：目标 ±1dp。
- App bar、按钮、Tab bar、列表行高度：目标 ±2dp。
- 卡片圆角：目标 ±1dp。
- 文本基线：目标 ±2dp；多行文本整体高度 ±4dp。
- 图标可见尺寸：目标 ±1dp；触控区不得小于 44dp。
- 计时环直径和中心位置：目标 ±2dp。
- 媒体焦点：角色眼睛中心偏移不超过画面宽/高的 2%。
- 主 CTA 在所有设备不得被安全区、键盘或 Tab bar 遮挡。

超出公差必须修复或记录经批准的设计变更，不能通过更新基线掩盖。

## 7. 颜色与文字验收

- 主题原语与文档十六进制值完全一致。
- 截图采样颜色允许因平台合成产生 `ΔE 2000 ≤ 2.5`。
- 正文与背景对比至少 4.5:1；大字至少 3:1；可操作图形至少 3:1。
- 主按钮同屏唯一；次操作不得使用相同面积和对比度。
- 动态数字使用 tabular numbers，不因秒数变化导致左右跳动。
- 不存在原型图栅格文字、Emoji、Unicode 图标或不可本地化字符串。

## 8. 自动视觉回归门禁

使用确定性 poster 和 fixture 截图。建议采用 SSIM + 结构区域断言：

- 全屏 SSIM：`≥ 0.985`。
- 去除媒体内容区后的 UI SSIM：`≥ 0.995`。
- 任一关键组件边界像素差异面积：`≤ 0.5%`。
- 不允许通过扩大 mask 排除按钮、文字、计时、价格、成就和榜单。
- 可 mask：系统状态栏时间、平台无法固定的抗锯齿边缘、真实视频内容区。

首次实现由设计/产品人工批准 baseline。之后更新 baseline 必须附：

1. 变更原因。
2. 旧/新并排图。
3. 影响页面和状态。
4. 产品批准人。

CI 不允许自动接受新基线。

## 9. 真机视觉验收

自动截图不能替代真机。每个候选版本至少检查：

- OLED 暗色下黑位、边界和文字是否糊成一片。
- 中端 Android 连续视频切换是否闪黑或掉帧。
- iPhone 刘海/灵动岛和 Android 异形屏是否遮挡标题。
- 锁屏恢复后视频、计时和控制层是否保持正确层级。
- 弱网时 poster 到视频切换是否改变构图。
- 系统字体 1.3×、读屏、减少动态和高对比设置。
- Plus 购买页真实商店本地化价格是否溢出。

验收证据包含设备型号、系统版本、App build、录屏/截图和未验证项。

## 10. 逐 PR 设计检查清单

- [ ] 页面唯一焦点与逐屏规格一致。
- [ ] 只使用语义令牌，没有页面私有颜色和随机间距。
- [ ] 使用已有组件；重复结构已提取。
- [ ] 默认、按下、焦点、禁用、加载、空、错误和离线状态完整。
- [ ] 关键控件触控区 ≥44×44，SVG 有语义标签。
- [ ] 视频失败、减少动态和离线不会改变核心页面几何。
- [ ] 三种屏幕宽度和 1.3× 字体截图通过。
- [ ] 与批准基线并排检查，无未经说明的漂移。
- [ ] 商店价格和权益来自真实服务端/商店 fixture，不是硬编码。
- [ ] 产品/设计审核人在 PR 上明确批准，而非仅由开发自审。

## 11. 完成定义

“与设计图一致”只有在以下证据同时存在时成立：

1. 功能和状态测试通过。
2. 逐屏几何公差通过。
3. 自动视觉回归通过。
4. iOS 与 Android 真机检查通过。
5. 视频连续性录屏通过。
6. 产品/设计人工批准。

缺少任何一项，只能称为“功能实现”，不能称为“设计完成”。
